# 一起把好作品留下来

感谢你分享作品、提示词、复现记录，或指出错误。无需懂代码，也可以参与。

## 用表单投稿

1. 登录 GitHub，打开 [投稿表单](https://github.com/zender555/awesome-gpt6/issues/new?template=submit-case.yml)。
2. 填写分类、标题、原始来源、作者、模型证据和提示词状态。可附可公开访问的截图或演示链接。
3. 提交后，由维护者核对来源、署名和证据，再整理进案例目录。缺少信息时会在 Issue 中补充沟通。

## 用 Pull Request 投稿

1. Fork 仓库，创建自己的分支。
2. 复制 [templates/case.md](templates/case.md) 到对应的 `cases/3d/`、`cases/web/`、`cases/video/` 或 `cases/games/`，文件名使用英文短横线，如 `interactive-gallery.md`。
3. 填好模板，在该分类的 `README.md` 添加一条链接。首页只保留少量精选，普通新增案例不必修改首页。
4. 本地运行 `node scripts/check.mjs`，然后发起 Pull Request。GitHub Actions 会检查本地链接、案例必填栏目与基本文件规范。

## 什么值得收录

- 具体作品或可操作的创作过程，有原始来源和作者署名。
- 模型版本能追溯；只看到转述时，明确标记“二手线索”。
- 提示词分别标为“作者原文 / 作者摘要 / 整理者改写 / 未公开”。没有完整提示词也可以投稿。
- 区分“官方展示 / 作者自述 / 二手线索”和“未复现 / 部分复现 / 已复现”；不能用阅读了帖子代替实测。
- 如称已复现，须提供日期、环境、步骤和结果证据。失败与局限也有参考价值。
- 视频案例说明 GPT‑6 在流程中的实际作用，以及使用的渲染、剪辑或生成工具。

不收录无来源的能力宣传、伪造对比、批量重复条目或泄露个人信息的素材。请只上传有权分享的文件；大型视频和工程文件放在原作者的发布渠道，以链接引用。

## 审核与署名

Issue 是投稿队列，Pull Request 是修改建议。维护者审核后合并，不自动发布，也无需给投稿者仓库写权限。你的 GitHub 提交记录会保留，案例中的原作者署名也会保留。

提交自有原创内容表示同意按本仓库 MIT 许可提供该部分内容；第三方内容需单独标明许可，未获授权时仅提供链接和简短原创摘要。

友善讨论，评价作品与证据，避免人身攻击。错误、侵权或撤回请求请使用 [纠错表单](https://github.com/zender555/awesome-gpt6/issues/new?template=correction.yml)。
